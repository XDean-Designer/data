一句话结论：线上链路不是没有降级路径，而是降级路径只有一半—— 拒绝定位后只能「手工创建新门店」，系统不允许后只能「去设置」，已被认领后只能「申请加入」。 三条旁路都只有一个出口，用户有店却被迫新建、有凭证却无处提交。 对标的共同做法是：每条旁路都留两个出口（搜索 / 创建、搜索 / 设置、加入 / 申诉）。

02 · 已撤回的结论（v1.0 勘误）

v1.0 把交互原型当成了线上系统，因此有 4 条判断不成立。原文保留在此以便对照，正文与改进清单已不再采用。

v1.0 结论实拍真相处理
登录页「一键登录 / 验证码 / 一键体验」三入口并列，主次不清 线上只有两个入口：本机一键登录、手机验证码登录。没有「一键体验」 整条撤回
定位「拒绝即停在登录」，是硬门槛与死路 线上有降级：拒绝 → 空态门店列表，可手工创建；系统不允许 → 授权失败 →「去设置」 撤回，改为判断「降级路径是否够用」
开店资料是一张长表单，一次填完、无分段 线上已经是 3 步（第 1 / 2 / 3 步） 撤回，改为待核「3 步内是否有进度、草稿、即时校验」
「落点写死首页、缺问需」是本文档要修的问题 问题真实存在，但另一份文档已定案四选一分流与四版块承接 不再重复提方案，仅引用

05 · 逐家拆解与证据

抖音来客 本地生活 · 门店发现的两条旁路最完整

  • 材料前置：首页可查看入驻「所需材料」，准备好再开始。
  • 搜索优先，不依赖定位：进入门店搜索页搜店 → 确认信息。
  • 两条旁路都给出口：「门店信息有误，可以编辑修改」「找不到需要认领的门店，可以创建门店」。
  • 少填一个字段：经营品类默认带入 POI 类目，商家只补执照里有的经营范围。
  • 审核可预期：1–3 工作日、首页「审核详情」、短信通知、不通过按提示改后重提。
  • 能力分层：入驻通过后才绑收款账户与抖音号。

「搜索需要认领的门店，并确认门店信息：a. 如果门店信息有误，可以编辑修改；b. 如果找不到需要认领的门店，可以创建门店。」

来源：抖音来客 APP 产品功能用户使用手册 · 2.2

美团商家 本地生活 · 认领冲突有申诉通道

  • 进度可视：开店宝固定 4 步——选择门店 → 提交材料 → 等待审核 → 完成认领。
  • 被占店有出口：门店已被他人认领，可提交营业执照与身份证信息及门店名称、地址，信息相符即认定为恶意认领，由平台处理。
  • 重复建店有提示：提交被驳回且提示「平台已收录」时，说明与已有门店高度重合，要求去系统里选择已有门店而不是继续新建。
  • 时效与驳回：约 3 个工作日、短信通知；驳回后按提示改材料再提交。

「已被他人认领，您可以向在线客服提交营业执照和身份证信息及门店名称、门店地址，如果执照信息与门店信息相符，就认为是被恶意认领。」

来源：商家客服知识库；开店宝 · 商家入驻；酒店商家入驻 FAQ

有赞 电商 SaaS · 把字段问少

  • 六步拆解：选主体与类目 → 短信验证 → 主体信息 → 法人信息 → 经营信息 → 审核及公示。
  • 能搜就不填：主体信息可按企业名称或统一社会信用代码模糊搜索，自动带出免填。
  • 材料清单随选择变化：主体类型与类目不同，所需材料不同；最多可选 5 个类目。
  • 渐进权限：审核期间可正常操作，但不能提现。
  • 反例：提交后不可撤回 / 修改，只能等审核结束；不通过需重新提交。

来源：店铺主体信息认证教程；店铺认证使用教程

微盟 电商 SaaS · 门槛最低

  • 手机号 + 验证码即可注册，主按钮写「免费创建店铺」而非「注册账号」。
  • 协议链接紧跟按钮（《注册协议》《个人信息处理规则》），不额外占一屏。
  • 店铺认证、公众号 / 小程序授权、微信支付开通各自独立，按需再走。

来源：微盟 · 账号注册

千牛 / 淘宝 电商平台 · 给「可能填错」的字段留额度

  • 淘宝账号与支付宝双实名，主体须一致，否则直接驳回。
  • 开店流程内完成支付宝认证 + 实人扫脸（法人或实际经营人）。
  • 店铺名开店后 180 天内可改 3 次——把易错字段的修改成本显式化。
  • 开店后 5 周不发商品，店铺会被删除（用后续动作驱动上线）。

来源：天猫招商 · 入驻流程；淘宝开店产品白皮书（二手，仅补细节）

企业微信 协同 · 渐进式准入

  • 先能用：企业名 / 行业 / 规模 + 管理员手机验证 + 微信扫码即可开始用。
  • 再解锁：上传营业执照「认领企业」后，成员上限 1000 人并开放更多 OA 能力。
  • 验证多选一：对公打款 / 法人扫脸 / 电子营业执照，按实际情况挑最省事的一种。
  • 材料示例：认证页给公函示例与材料清单，减少「交了才知道不对」。

来源：创建并注册企业；管理端认证说明

5.1 横向依据：定位权限

请求前先说明，拒绝后给替代
  • 预提示：先讲「为什么需要、只在前台用」，用户点了肯定回应再触发系统弹窗。
  • 数据：无用户意图的权限弹窗约 12% 被允许；有交互后升到约 30%。
  • 拒绝后必须给备选方案（手动输入地址 / 选城市），不得强制授权，48 小时内不得重复索权。
  • 抖音开放平台对未授权场景明确「推荐提供手动选择地理位置的能力」。

web.dev · 小米 · 抖音开放平台

对线上链路的直接含义
  • 线上已有「说明 → 系统权限」两段，这一段做对了，不需要重做。
  • 缺的是「拒绝之后」：空态只给「手工创建新门店」，等于把「我有店」的用户推向「新建一家店」。
  • 行业做法是同日径给两个出口：按名称搜索已有门店 + 找不到才创建。

07 · 改进清单

7.1 P0 · 每条旁路补齐第二个出口

#改进实拍证据对标出处落点
P0-1 拒绝定位后的空态加「按名称搜索门店」：空态从「暂无内容 + 手工创建」改为「搜索框 + 附近推荐 + 找不到再创建」 泳道② 拒绝后空态，仅「可手工创建新门店」 抖音来客：搜索门店 → 找不到才创建；美团开店宝「选择门店」 门店列表空态；搜索复用认领页搜索能力

7.2 P1 · 补预期与省字段

#改进实拍证据对标出处落点
P1-1 材料清单前置：封面或登录后一张「开店要准备」清单（执照 / 门店照 / 收款信息 / 门店地址），可勾选 实拍无材料预告，第 3 步才暴露所需材料 抖音来客首页「所需材料」；企业微信「认证需准备的材料」 封面次区域或登录后一次性提示
P1-2 门店信息可编辑：认领确认页允许就地改门店名称 / 地址，改动标记待审核 实拍无编辑入口 抖音来客「门店信息有误可以编辑修改」 认领确认页

7.3 待核项（先确认再决定改不改）

#疑点若答案为「没有」，则改对标出处
TBD-1 3 步表单是否有进度提示、草稿保存、即时校验 补「第 N / 3 步 + 还需 N 项 + 已保存」；离开可续填 有赞 6 步；SaaS 表单「拆步 + 可见终点 + 自动保存」
TBD-2 提交后是否有审核中 / 驳回重传态（含首页审核卡片） 补审核屏：进度 + 预计 1–3 工作日 + 驳回原因 + 只改被驳回项 抖音审核详情 + 短信 + 驳回重提；美团 4 步；天猫 7 工作日 + 15 日修改窗口
取舍：P0 三项都只加「第二个出口」，不删现有路径——线上已有「手工创建」「去设置」「申请加入」三条路， 改动是并列补一条，不是推翻重做，风险与成本都可控。

08 · 数据导入：新增功能的设计要点

定位说明：数据导入线上尚不存在，目前处于产品原型阶段。 这一段以原型为准，按「新增功能」设计，不属于修复线上问题；本节给的是新功能该长什么样，不是线上缺陷。

8.1 原型已有能力（作为设计基线）

  • 链路：选择对象 → 数据来源 → 映射确认 → 核对数据 → 导入结果 → 失败明细。
  • 核对页分两层：分类概览（唯一可确认导入的闸口）+ 单一类别明细（只读，不可导入）。
  • 失败行有就地半屏补录通道，不必整批重来。
  • 样表基准：members.xlsx —— 会员编号 / 姓名 / 首字母 / 手机号 / 卡种 / 卡有效期 / 储值余额 / 充值合计 / 消费合计 / 消费笔数 / 距今天数 / 支付方式。

8.2 新增功能值得借鉴的 4 条

#设计要点对标出处为什么需要
N-1 样表与字段清单前置：选来源页给「推荐格式」（即 members.xlsx 的 12 列）+「你的表差哪几列」 抖音来客「首页可查看所需材料」；企业微信「认证需准备的材料」 老店导出的表五花八门，先对齐字段能大幅降低映射失败
N-2 映射可回改：映射页确认后仍能从核对页返回改映射，不清空已识别数据 SaaS 表单「允许回退且不丢已填内容」 映射错了要能只改一行，而不是整批重来
N-3 用途与可撤回说明：选来源页一行「仅本店可见 · 仅用于建会员 / 卡 / 价目 · 可整批删除」；结果页给「删除本批」 有赞主体认证的用途与协议明示；企业微信认证材料与用途说明 会员表是老店最敏感资产，说不清用途就不敢传
N-4 防重复导入：确认按钮 loading + 禁用；结果未知时给「查询本批状态」而不是再点一次 SaaS 表单最佳实践：防双击、按钮显示进度 重复导入会产生重复会员与重复余额
落地状态：N-1 ～ N-4 已按上表落到交互原型（线上尚无数据导入，以原型为准）。 对应改动：数据来源页（N-1 / N-3）、映射确认页（N-2）、核对页（N-4）、导入结果页（N-3 / N-4）。

09 · 改后动线与信任感

9.1 线上入驻段改后动线

① 封面

价值主张 + 一句准备

保留品牌与价值主张；补一行「开店约 3 分钟，需准备执照、门店照、门店地址」，可展开细项。

② 登录

保持两个入口

本机一键登录 + 手机验证码登录，已符合行业做法（微盟同构），本轮不动。

③ 定位

说明与系统权限保持不变

这一段线上已做对：先 App 内说明、再系统弹窗。不改。

④ 门店列表

三条分支各补第二个出口

允许：附近门店（不变）。拒绝：空态改为「搜索门店 + 附近推荐 + 找不到再创建」。不允许：授权失败页加「暂不开启，按城市 / 名称查找」。

⑤ 认领

信息可改，冲突可申诉

认领确认页允许改名称 / 地址；「已被认领」弹窗给三选一：取消 · 申请加入 · 我是店主提交凭证。

⑥ 填资料

3 步保留，补进度与可续

顶部「第 N / 3 步 · 还需 N 项」；离开再回已填内容仍在（若线上已具备则不动，见 TBD-1）。

⑦ 提交之后

有审核态才叫走完

审核中：进度 + 预计 1–3 个工作日 + 可否补材料；驳回：原因 + 只改被驳回项（若线上已具备则不动，见 TBD-2）。

9.2 与分流 / 承接的边界（仅引用，不重提方案）

实拍泳道③ 显示「走完开店，随即进入首页」、泳道④ 显示「获客无新手引导、发布活动撞上价目表死结」。 这两件事已由《开店分流与承接方案》定案：开店完成插入四选一问需并跳转高亮 TAB；获客在发布路径内就地建 1 个项目。 本文档不重复设计，只确认一件事：分流必须发生在落到首页之前，否则本文档补的「审核态」之后会直接掉进未分流首页。

9.3 信任感：把四处不确定逐条消掉

线上触点用户心里的话补什么对标
拒绝定位后的空态 「不让我定位，是不是就不给我找店了？」 明说「不开定位也能按名称找店」，并真给搜索框 抖音开放平台手动选位置；小米备选方案
系统权限不允许 「我不想去设置里翻。」 「暂不开启」可继续走，不重复索权 小米 48 小时索权上限
门店已被认领 「这明明是我的店，凭什么说他认领了？」 给凭证申诉入口，说清核验依据与处理时效 美团「信息相符即认定为恶意认领」
提交开店之后 「我提交了，然后呢？」 审核态 + 预计时长 + 结果通知方式 抖音审核详情 + 短信；天猫 7 工作日
导入会员表（新增） 「这是我家全部客人，能随便传吗？」 用途一行 + 仅本店可见 + 可整批删除 有赞主体认证的用途与协议明示

10 · 待核清单与验收口径

10.1 待核清单（需线上确认，本文档不预设答案）

#要确认的事确认方式影响
TBD-1 3 步表单内是否有进度、草稿、即时校验、剩余项 线上走一遍 3 步，故意中途退出再进 决定是否需要补草稿与进度
TBD-2 提交后是否有审核中 / 驳回态；首页是否有审核卡片 线上提交一单，观察首页与消息 决定是否需要补审核屏
TBD-3 定位说明弹窗的原文与「拒绝」按钮文案 截图核对 决定是否需要改文案（不改流程）
TBD-4 「申请加入」之后是什么流程（谁审批、多久） 点进去走一遍 决定申诉通道是否可与它合并

10.2 验收口径（按规格写，待实现后核对）

  • 拒绝定位：空态出现搜索框，能按名称搜到已有门店；搜不到才引导创建。
  • 系统不允许：授权失败页除「去设置」外有「暂不开启」；选它可继续按城市 / 名称找店，且不再弹系统权限。
  • 已被认领：弹窗有三个选项；选「我是店主提交凭证」可上传执照、身份证并提交，有受理反馈。
  • 材料清单：封面或登录后能看到开店所需材料，且与实际 3 步所收字段一致。
  • 门店信息：认领确认页可改名称 / 地址，改动有「待审核」标识。
  • 新增功能（数据导入）：选来源页有推荐格式与用途说明；映射可从核对页回改；确认按钮防重复；结果页可删除本批。

10.3 本轮不做

  • 不改分流与承接（另一份文档已定案）。
  • 不重做「定位说明 → 系统权限」两段（线上已符合行业做法）。
  • 不引入第三方登录 / 微信授权登录。
  • 不做真实审核中台、短信通道与人工核验后台（本文档只定前端与流程口径）。
  • 不做视觉改版；只改信息结构与出口。
